# Архитектура: как устроена охота

## Цепочка Jio (то, что делает код)

```
провайдер SMS        Jio selfcare API                      Google
──────────────       ─────────────────────────────         ─────────
rent ──► номер ──►   check_number (иногда 429, ок)
                      sendOtp  ──► SMS ──► код у провайдера
                      validateOtp ──► auth-куки (вся сессия = куки)
                      navigate(Z0241) ─► activate(Z0241)
                      google-ai ─► redirectionURL ─────────► активация
```

`Z0241` — код предложения Google AI Pro в OTT-агрегаторе Jio. Ответ
`google-ai` содержит `redirectionURL` — ссылку вида
`serviceactivation.google.com/subscription/new/<токен>`. Если Jio вернул
HTML вместо JSON, ссылка вытаскивается регэкспом по маркерам
(`serviceactivation.google.com`, `one.google.com/activate-plan`,
`partnerPromotionToken`).

## Модули

| Модуль | Ответственность |
|---|---|
| `cli.py` | команды typer: `run/hunt/balance/links/check/bot/relink` |
| `runner.py` | `Farm` (цикл, дедуп, доставка) и `FarmManager` (супервизор для панели) |
| `panel.py` | экраны и кнопки админки |
| `bot.py` | Telegram-транспорт: сообщения, клавиатуры, колбэки, allowlist |
| `hunter.py` | одна охота: аренда → OTP → логин → активация → ссылка |
| `jio/auth.py` | sendOtp / validateOtp, коды ошибок Jio |
| `jio/hunt.py` | цепочка Z0241 и извлечение ссылки |
| `jio/relink.py` | восстановление сессии из cookie и перевыпуск токена |
| `jio/check.py` | проверка «абонент Jio?» |
| `pvacodes/`, `stacked/`, `grizzly/` | клиенты SMS-провайдеров за одним протоколом `sms.py` |
| `refund.py` | авто-отмена неудачных аренд и возврат денег |
| `proxy.py` | пул прокси: источники, проверка, ротация, sticky на охоту |
| `shield.py` | DoH-резолв, обходит локальные DNS-заглушки PVACodes |
| `storage/store.py` | таблица `hunts` |
| `storage/sessions.py` | таблица `sessions`: cookie-логины для relink |
| `checker.py` | проба ссылок и честная классификация |
| `links.py`, `runfile.py` | запись ссылок в файлы |

## Инварианты, которые держит код

1. **Ссылка в файл раньше уведомления** — мёртвый бот не съедает оплаченную
   ссылку (`hunter.hunt_once`).
2. **Деньги не сжигаются молча** — каждая неудачная ветка явно планирует
   возврат: NOT_JIO — мгновенно, OTP-отказ — по таймауту, исключение —
   через cancel.
3. **Одна охота = один прокси** — sendOtp, логин и активация уходят с одного
   IP, иначе Jio видит два разных клиента.
4. **Пустая кука не сохраняется** — сессия без cookie не пишется в базу,
   чтобы relink не поднимал мусор.
5. **Одна ссылка за охоту** — перевыпуск токена даёт N строк для одного
   предложения, поэтому доставка строго по одной.
6. **Бот слушает один чат** — и команды, и кнопки игнорируются от чужих
   чатов; токен не даёт управления фермой постороннему.
